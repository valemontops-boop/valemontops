# Decisions

One line each: what — why — how to reverse.

- D001 Next.js 16.4 App Router with `cacheComponents` (scaffold default); session reads live behind `<Suspense>` — current stable — remove flag in next.config.ts.
- D002 shadcn/ui primitives hand-written on `radix-ui` in `src/components/ui` — the shadcn registry (ui.shadcn.com) is unreachable from the build sandbox — run `npx shadcn add <c>` later and replace files one by one.
- D003 Sheets accessed through a thin `fetch` client (`src/data/sheets/client.ts`) instead of the `googleapis` package — full control of timeouts/retries and the same code path hits the fake server; tokens from `google-auth-library` — swap for `@googleapis/sheets` behind the same interface.
- D004 Every cell is written as a string with `valueInputOption=RAW` and parsed back through Zod — guarantees `+336…`, `-12.00`, `=SUM(A1)` survive unchanged — n/a (spec 4.5).
- D005 Columns are resolved by header name, not position; a missing header is an integrity warning — survives humans moving columns — n/a.
- D006 Creates use client/server-generated UUIDs and readers de-duplicate by `id` (earliest `created_at`), so a retried append cannot create a second logical record — makes append retry-safe without locks — n/a.
- D007 Activity events are their own audit trail (append-only); `AuditLog` records other mutations with field names only, never values — saves one Sheets call per log and keeps personal data out of logs — append an AuditLog row in `logActivity`.
- D008 Targets and work modes are append-only rows with `effective_from`; edits apply today only if today's `DailyPlans` snapshot does not exist yet, otherwise from tomorrow — spec 5.3 "plan snapshot at day start" — n/a.
- D009 The day plan snapshot is written lazily on the first My Day read of a scheduled local day (deterministic UUIDv5 id, earliest row wins) — no cron (spec 4.6) — n/a.
- D010 DEMO sign-in (pick Théo or Pablo, synthetic data) exists only when `APP_MODE=demo`; in production it additionally requires `DEMO_ACCESS_CODE` — makes the app usable before credentials exist without an auth bypass — remove `/api/auth/demo`.
- D011 No test-auth bypass is implemented at all; e2e tests use DEMO sign-in, service tests call services with an explicit actor — nothing to leak into production — n/a.
- D012 DEMO data can be served by the in-memory repository (`DEMO_BACKEND=memory`, default) or by the real Sheets adapter pointed at the local fake server (`DEMO_BACKEND=fake-sheets`) — exercises the whole Sheets path without credentials — n/a.
- D013 Stage 1A creates only the tabs it uses (listed in docs/SCHEMA.md); later stages add tabs through `setup:sheets` migrations — avoids designing 60 empty schemas now — n/a.
- D014 Private job-search data (separate spreadsheet per founder) is Stage 1B; Stage 1A has no job-application counter, so nothing private is in the shared Sheet — n/a.
- D015 Opt-out reversal is not offered in Stage 1A UI; suppression entries are append-only — safest default for a hard block — add an audited "lift with consent evidence" action in 1B.
- D016 Skills from spec §1 were loaded selectively (installed Next.js docs read directly) to keep context for implementation — n/a.
- D017 Accent changed from orange #E8920C to ink #17161A (on-accent #FBFAF7) — founders disliked the orange; the user's instruction overrides spec §8.1 — set `--accent`, `--accent-hover`, `--on-accent` in globals.css.
- D018 CRM simplified to a 5-column board (To contact · Contacted · In talks · Demo & proposal · Won) over the 10 stored stages, with "next step + date" as the first thing on every card and panel; the full stage list, ANUM and value sit under "More details" — founders asked for simpler CRM; RevOps guidance (5–7 stages, few fields, next step per deal) — change `PIPELINE_GROUPS` in src/domain/pipeline.ts.
- D019 Partial update schemas are built with `patchOf()` (src/lib/zod.ts) because zod v4 `.partial()` keeps `.default()` values and silently reset unsent fields (found by e2e: completing a task cleared its owner) — n/a.
- D020 LinkedIn XLSX parsed with exceljs; legacy XLS with SheetJS 0.18.5 from npm (cdn.sheetjs.com, where current versions live, is unreachable from the build sandbox). Known advisories on crafted files; mitigated by 2 MB limit, 5,000-row cap, founder-only upload — install the current SheetJS tarball from cdn.sheetjs.com when reachable.
- D021 Day closure reconstructs a missing plan from append-only modes/targets and the CURRENT workdays; high-priority follow-ups count as handled when the account was touched between due date and the day, or rescheduled later with a reason (enforced on the opportunity) — no cron, spec 4.6 — n/a.
- D022 Command Center "Cash balance" and "MRR" render "Not tracked yet" until Finance (Stage 3) instead of 0 — five slots always present (scenario 23), no fake numbers — replace when Stage 3 lands.
- D023 The other founder's personal calendar is always read with free/busy, even if shared with details, so their titles never reach the server response or Sheets — n/a.
- D024 Notifications are derived on read; only dismissals are stored (NotificationStates) — no background job — n/a.
- D025 Drive uploads use an encrypted httpOnly cookie holding the founder's own drive.file access token (online, ~1 h); expiry means asking again, never a fallback to the service account. DEMO simulates the grant — store an offline refresh token in the cookie later if re-consent is annoying.
- D026 Google Picker is not wired (needs a browser API key and Google's script); files are linked from the shared folder listing instead — add Picker when GOOGLE_PICKER_API_KEY exists.
- D027 Post-level social checkpoints (SocialPostSnapshots) and the snapshot job move with the Instagram adapter to Stage 3, as the commands file orders; Stage 1B stores daily account values (manual + LinkedIn import).
- D028 Idea conversion supports Task and Opportunity; Content Concept and Campaign targets arrive with Marketing content (Stage 3).
- D029 CRM pipeline holds only people who said yes (Talk again · Meeting booked · Met/demo · Proposal · Won); imported lists are call lists worked in call mode; refusals are ticks, not records — founders' request; spec 5.5 stages unchanged underneath — change PIPELINE_GROUPS.
- D030 Call mode: one tap = one ActivityEvent (idempotent); free-dialling refusals store only an HMAC of the normalised number (`target_key`) to count distinct businesses without keeping the number; a "yes" creates the business, contact and deal — data minimisation (spec 3.9) — store the number if the founders want call-backs on refusals.
- D031 Job search removed from the app (UI, API, JobApplications table) at the founders' request; the private spreadsheet keeps private tasks only — overrides spec 4.7/5.2 job-search parts.
- D032 Tasks have an area (sales / marketing / ops); My Day shows the three areas; empty legacy cells read as "sales" — n/a.
- D033 Weekly marketing deliverables (spec 5.6 targets per mode) are logged with one tap into ContentLog and shown in My Day and Marketing › Content; full content pipeline (Idea→Published) stays Stage 3.
- D034 Marketing decisions are deterministic rules with their evidence (audience in target markets <60 %, under-reached market <20 %, best source ≥1.3× average with ≥30 sessions, sources with ≥50 sessions and no conversion); no AI — thresholds in src/domain/marketing.ts.
- D035 Website traffic comes from GA4 CSV exports or manual entry (TrafficDaily) until a GA4 adapter (Stage 4); audience countries from LinkedIn "Location" sheets or a manual split from Instagram Insights (AudienceBreakdown).
- D036 Files is a Drive explorer over the shared folder tree (service account read; search and recent across the tree); new folders and uploads use the founder's drive.file grant — n/a.
- D037 Reports default to a visual dashboard (KPIs with deltas vs the previous period, daily chart, funnel, objections, best hours, country, trade); the CSV export remains for spreadsheets.
- D038 Objections are a multi-select list on every call (`ActivityEvents.objections`, JSON), whatever the outcome; `objection` keeps the first for older reports. Analytics show how often each one still ended in a yes ("won over") — founders' request.
- D039 Call mode keys: Enter dial, 1–7 outcomes read by physical key (`e.code`, so AZERTY needs no Shift), A S D F G H J K L objections, E email, P deck, W WhatsApp, C copy Calendly, N skip, Esc close. Global quick-action letters are disabled while a call session is open — n/a.
- D040 Gmail uses `gmail.send` only (spec 4.15): an encrypted httpOnly cookie with the founder's own short-lived token, never stored in Sheets; no inbox access, so replies are marked by a founder in one tap (Marketing › Email). The mail app and WhatsApp open prefilled and count only after "Yes, sent" (spec 5.4). A Gmail send that may have left but was not confirmed is never re-sent automatically. Spanish COLD email is blocked without recorded consent (LSSI art. 21); follow-ups after a call are allowed — add `gmail.metadata` for automatic reply detection only after a security review (restricted scope).
- D041 Report series colors: blue #2A78D6 = volume (dials, picked up, channels), teal #16946A = conversions (yes, meetings, won); validated with the dataviz palette checker on the panel surface (CVD ΔE 19.6, normal-vision ΔE 20.6, both ≥ 3:1). No orange, status colors stay reserved; FR/ES keep ink/grey (spec 8) — change `--viz-*` in globals.css and re-run the checker.
- D042 Email benchmarks divide replies by emails sent and compare only COLD emails with public ranges (1–5 % typical, 5–10 % strong; sources in src/domain/email.ts); emails after a call are warm and judged against our own trend. Below `conversion_min_sample` (default 20) a segment says "not enough data". No open-tracking pixels.
- D043 Playbook (opener, objection replies, emails, WhatsApp; FR and ES) ships built-in defaults in code; founder edits are rows in the `Playbook` tab that override them; an empty body returns to the default. Calendly per founder and deck links (FR/ES) are Workspace settings (https only).
- D044 One color system for the whole app: blue = sales activity, green = results, violet = marketing, teal = ops, ink = the one headline; tiles take the soft tint of their area. Colorblind validation dropped at the founders' request (D041 superseded); brand Local moves from orange to rose — tokens in globals.css and src/lib/tones.ts.
- D045 Objections v3, from call research (Gong Labs analysis of cold-call objections; brush-off vs real triage; label + calibrated question; always end on a next step): 12 live objections split into brush-offs and real objections; each reply is three lines (Label / Ask / Next step) with two variants per language. Calls store the variant used (`ActivityEvents.replies`); the app shows the least-tried variant until each has 5 uses, then the one with the best smoothed win rate. A 2-second pause cue, a "what it usually means" line, and an objection drill on the Call mode start screen — change texts in Settings › Playbook.
- D046 Volume of messages: every outcome suggests a message (thank-you, Calendly, deck, confirmation, "thank you, door open" after a no, "tried to reach you" after no answer), key M sends it (Gmail directly when connected), and Call mode lists everyone still owed a message (reached in the last 2 days, no answer today, no reply after 3 days → one nudge) with "Send all by Gmail" after review. Founder click = explicit human action (spec 4.15); nothing is sent on a schedule. Cold messages (no conversation) are never queued for Spain without recorded consent, email or WhatsApp (LSSI art. 21); free-dial refusals get no message (no number kept, D030).
- D047 Sober UI (supersedes D044): ink + one blue for data, green only for results (yes, meetings, won, income); no tinted tiles, no colored menu, plain section headings. Founders found round 4 "bariolé" — tokens in globals.css (`--sales*`, `--win*`, `--mkt*`, `--ops*` now map to blue/panel).
- D048 No English UI (overrides CLAUDE.md "UI in English"): Théo reads French, Pablo reads Spanish (`LOCALE_OF` in src/i18n). English strings in code are keys; dictionaries in src/i18n/dict/*.ts map them to [FR, ES]; keys with {placeholders} also match server sentences as patterns. API error messages are translated in route() for the signed-in founder; the WhatsApp report is built in the founder's language. Prospect-facing texts (playbook, emails) stay in the prospect's language (FR/ES). Login/setup pick FR or ES from Accept-Language.
- D049 Wise (read-only) for the Money page: balances (`/v4/profiles/{id}/balances`), statements (`/v1/.../statement.json`) with the SCA one-time-token signed by our RSA key when Wise asks (key optional; without it, statements are skipped and a CSV statement import is offered), and live movements by the `balances#update` webhook verified with Wise's RSA public key (X-Signature-SHA256). Movements land in `BankTransactions` (idempotent by Wise reference; a live row is completed, never duplicated, when the statement arrives), balances in `BankBalances`. Auto categories (spec 6: founder contributions and transfers between our balances are neither income nor expense); credits auto-tagged as income are "to check" until a founder confirms. Read-only token: the app can never move money. Wise reports that key-based SCA signing may be refused for some account types — hence the CSV fallback.
- D050 Marketing is a funnel analysis of every channel (calls, field visits, LinkedIn, email, WhatsApp, website & social): touches → replies/conversations → yes → meetings → won, with meetings per hour of work (minutes per action) and last-touch attribution of meetings and wins. Social audience and website traffic stay as sub-tabs.
- D051 Call screen simplified: one column, counts as a line of text, compact objection chips with a 3-line reply, one slim "message for X" bar after the outcome, composer in a dialog, keyboard help folded. Call mode start: tabs Call · Messages · Objections.
